# AI Usage Disclosure — ASTRA INTEL

> This document discloses every use of AI tools during the design, development, debugging, and documentation of ASTRA INTEL, in accordance with competition/submission transparency requirements.

---

## Summary

AI coding assistants were used **throughout** this project as an accelerant — for code generation, debugging, architecture discussion, and documentation writing. All generated output was reviewed, understood, tested, and often manually edited before being committed. No AI-generated content was accepted blindly.

## Tools Used

| Tool | Provider | Role |
|---|---|---|
| **Antigravity IDE (Claude Sonnet)** | Google DeepMind / Anthropic | Primary coding assistant — architecture, code generation, debugging, documentation |

| **all-MiniLM-L6-v2** | Hugging Face / SBERT | Local embedding model used at runtime for semantic vector search |

## Detailed Disclosure by Phase

### 1. Architecture & Design

- The overall **5-step RAG pipeline** (Extract → Chunk → Embed → Retrieve → Synthesise) was designed collaboratively with an AI assistant, which explained trade-offs between approaches (e.g. fixed-size vs semantic chunking, cloud vs local embeddings).
- The decision to use **local embeddings** for the indexing phase and a **cloud LLM** only for final answer synthesis was discussed with the assistant to meet the privacy-first design goal.
- The **overlapping chunking strategy** (180-word windows, 40-word overlap) and MIN_SCORE threshold design were informed by AI-suggested best practices for RAG retrieval quality.

### 2. Code Generation

#### src/rag.py
- extract_pages / _ocr_page: Initial structure generated by AI; OCR fallback logic (< 20 characters heuristic) suggested by assistant.
- chunk_pages: Step/overlap calculation and the minimum-chunk-length guard (>= 15 words) proposed by assistant.
- DocIndex.__init__ / search: Core vector indexing pattern (normalised embeddings + matrix dot product for cosine similarity) generated by assistant.
- _chat / _get_client: Singleton client pattern and Qwen3 think-tag stripping regex both suggested by assistant.
- answer: The NOT_FOUND sentinel pattern and multi-turn history slicing ([-3:]) generated by assistant.
- summarize / suggest_questions: np.linspace sampling approach for evenly-spaced chunk selection suggested by assistant.

#### src/app.py
- CSS injection block: Dark tactical theme generated by AI with human direction on colour palette.
- Session state architecture: setdefault pattern for all five session state keys was AI-suggested.
- Source card HTML: The page-badge + passage-text layout was generated by AI and fine-tuned manually.
- html.escape usage: XSS-prevention approach suggested by assistant.

#### tests/eval.py
- sys.path.insert bootstrapping: Pattern for importing src/rag.py from the tests/ directory suggested by assistant.
- Top-1 / Top-K accuracy metric computation: Suggested by assistant as the standard RAG retrieval evaluation methodology.

### 3. Debugging

The following bugs were identified and fixed with AI assistance:

| Bug | File | Description |
|---|---|---|
| Wrong DocIndex call signature | tests/eval.py | Passed two positional args instead of List[Tuple[bytes, str]]; fixed to DocIndex([(pdf_bytes, pdf_path)]) |
| TypeError: object of type 'int' has no len() | src/app.py | ss.index.pages is an int counter, not a collection; len() wrapper incorrectly applied and removed |

### 4. Documentation

- README.md was substantially rewritten by an AI assistant based on a full reading of all source files. Section structure, tables, mermaid diagram, and attribute tables were all AI-generated. All technical details were verified against the actual code.
- This AI_USAGE.md disclosure was written with AI assistance to ensure completeness and clarity.

## What Was Done Without AI

- Product concept and naming (ASTRA INTEL, the defence-intelligence framing) — original human idea.
- Final QA and testing — manually running the Streamlit app against real PDFs.
- API key management and .env setup — manual.
- All editorial decisions about what code to accept, reject, or modify from AI suggestions.

---

## Responsible Use Notes

- All AI-generated code suggestions were read and understood before being committed.
- The LLM used at runtime operates under a strict grounding constraint: it is instructed to answer using only the provided document excerpts and to reply NOT_FOUND if the answer is absent.
- No training data, fine-tuning, or model customisation was performed.
- No personal or sensitive user data was sent to any external service during development.
