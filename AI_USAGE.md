# AI Usage Disclosure — ASTRA INTEL

> This document discloses the use of AI tools during the development of ASTRA INTEL, in accordance with competition/submission transparency requirements.

---

## Summary

The architecture and design of ASTRA INTEL — including the RAG pipeline structure, technology choices, and component breakdown — were conceived and specified by the developer. An AI assistant (Claude via Antigravity IDE) was used to help produce the documentation (README.md and this file) based on that architecture. All code was written and owned by the developer.

---

## Tools Used

| Tool | Provider | Role |
|---|---|---|
| **Antigravity IDE (Claude Sonnet)** | Google DeepMind / Anthropic | Documentation assistance |
| **Groq API + Qwen LLM** | Groq / Alibaba Cloud | Runtime LLM powering Q&A, summarisation, and question suggestion inside the app |
| **all-MiniLM-L6-v2** | Hugging Face / SBERT | Local embedding model used at runtime for semantic vector search |

---

## Detailed Disclosure

### 1. Architecture & Design

The architecture was **designed by the developer** — including the decision to use a 5-step RAG pipeline (Extract → Chunk → Embed → Retrieve → Synthesise), local embeddings for privacy, Groq/Qwen for LLM inference, and the overlapping chunking strategy. The developer described this architecture to the AI assistant, which then used it as the basis for documentation.

### 2. Code

All source code (`src/app.py`, `src/rag.py`, `tests/eval.py`) was written by the developer. No code was generated by AI.

### 3. Documentation

- `README.md` — written by an AI assistant based on the architecture and codebase described by the developer. All technical details were verified against the actual code before submission.
- `AI_USAGE.md` — written with AI assistance based on the developer's description of what was and wasn't AI-assisted.

---

## What Was Done Without AI

- Product concept, name, and defence-intelligence framing (ASTRA INTEL) — original developer idea
- Full system architecture and all technical design decisions
- All source code implementation
- Technology selection (Streamlit, PyMuPDF, SentenceTransformers, Groq, NumPy)
- Manual QA and testing against real PDF documents
- API key management and environment setup

---

## Responsible Use Notes

- The LLM used at runtime operates under a strict grounding constraint: it answers using only the provided document excerpts and replies with a clear rejection if the answer is not found.
- No training data, fine-tuning, or model customisation was performed.
- No personal or sensitive user data was sent to any external service during development.
